# RiverFlow 插件开发指南

## 一、插件化架构概述

RiverFlow支持通过插件机制扩展流程节点类型，无需修改核心代码即可添加新的节点功能。

### 核心特性

- ✅ **动态加载**：JAR包放入plugins目录自动加载
- ✅ **零侵入**：无需修改核心代码
- ✅ **热插拔**：支持运行时重新加载插件
- ✅ **标准化**：基于Java SPI机制
- ✅ **前后端一体**：支持前端UI组件扩展

## 二、插件开发步骤

### 2.1 创建插件项目

1. 创建Maven项目，添加依赖：

```xml
<dependencies>
    <dependency>
        <groupId>com.riverflow</groupId>
        <artifactId>riverflow-api</artifactId>
        <scope>provided</scope>
    </dependency>
    
    <!-- 其他依赖，如MinIO SDK -->
    <dependency>
        <groupId>io.minio</groupId>
        <artifactId>minio</artifactId>
        <version>8.5.7</version>
    </dependency>
</dependencies>
```

2. 实现NodePlugin接口：

```java
public class MyPlugin implements NodePlugin {
    
    @Override
    public String getNodeType() {
        return "my-node"; // 唯一标识
    }
    
    @Override
    public String getNodeName() {
        return "我的自定义节点";
    }
    
    @Override
    public String getIcon() {
        return "Star"; // Element Plus图标
    }
    
    @Override
    public String getCategory() {
        return "custom";
    }
    
    @Override
    public String getDescription() {
        return "节点描述";
    }
    
    @Override
    public String getConfigTemplate() {
        // 返回默认配置JSON
        return "{\"param1\": \"value1\"}";
    }
    
    @Override
    public NodePluginResult execute(FlowNode node, Map<String, Object> context) {
        // 实现节点逻辑
        try {
            JSONObject config = JSON.parseObject(node.getConfigJson());
            
            // 执行业务逻辑
            Map<String, Object> result = new HashMap<>();
            result.put("success", true);
            
            return NodePluginResult.success(result);
        } catch (Exception e) {
            return NodePluginResult.fail(e.getMessage());
        }
    }
}
```

3. 注册SPI服务：

在 `src/main/resources/META-INF/services/` 目录下创建文件：
```
com.riverflow.api.plugin.NodePlugin
```

文件内容为实现类全路径：
```
com.mycompany.plugin.MyPlugin
```

4. 打包插件：

```bash
mvn clean package
```

生成的JAR包放入 `plugins/` 目录即可。

### 2.2 开发前端组件（可选）

1. 创建Vue组件：

```vue
<template>
  <div class="my-node-config">
    <el-form :model="config">
      <el-form-item label="参数1">
        <el-input v-model="config.param1" />
      </el-form-item>
    </el-form>
  </div>
</template>

<script setup>
import { ref, watch } from 'vue'

const props = defineProps({
  modelValue: String
})

const emit = defineEmits(['update:modelValue'])

const config = ref({})

watch(config, (val) => {
  emit('update:modelValue', JSON.stringify(val))
}, { deep: true })
</script>
```

2. 创建index.js导出：

```javascript
import MyNodeConfig from './components/MyNodeConfig.vue'

export default {
  'my-node': {
    name: '我的自定义节点',
    icon: 'Star',
    component: MyNodeConfig
  }
}
```

## 三、MinIO插件使用示例

### 3.1 编译安装

```bash
cd river-minio
mvn clean package
```

将生成的 `river-minio-1.0.0-SNAPSHOT.jar` 复制到 `plugins/` 目录。

### 3.2 配置MinIO节点

在流程设计器中添加MinIO节点，配置如下：

```json
{
  "endpoint": "http://192.168.1.100:9000",
  "accessKey": "minioadmin",
  "secretKey": "minioadmin",
  "bucket": "materials",
  "operation": "upload",
  "objectName": "${context.fileName}",
  "filePath": "${context.filePath}"
}
```

### 3.3 流程上下文传递

上游节点准备文件信息：

```groovy
// Script节点
context.filePath = "/tmp/report.pdf"
context.fileName = "report_${System.currentTimeMillis()}.pdf"
```

MinIO节点自动从上下文获取参数并上传文件。

### 3.4 查看上传结果

MinIO节点执行成功后，会在上下文中输出：

```json
{
  "success": true,
  "bucket": "materials",
  "objectName": "report_1234567890.pdf",
  "url": "http://192.168.1.100:9000/materials/report_1234567890.pdf",
  "operation": "upload"
}
```

下游节点可以通过 `${context.url}` 引用上传后的URL。

## 四、插件API说明

### 4.1 NodePlugin接口

| 方法 | 说明 | 必须实现 |
|------|------|---------|
| getNodeType() | 节点类型标识（唯一） | ✅ |
| getNodeName() | 节点显示名称 | ✅ |
| getIcon() | Element Plus图标名称 | ✅ |
| getCategory() | 节点分类 | ✅ |
| getDescription() | 节点描述 | ✅ |
| getConfigTemplate() | 默认配置模板JSON | ✅ |
| execute() | 执行节点逻辑 | ✅ |
| validateConfig() | 验证配置有效性 | ❌ |

### 4.2 NodePluginResult

```java
// 成功
NodePluginResult.success()
NodePluginResult.success(data)

// 失败
NodePluginResult.fail("错误信息")

// 等待（异步操作）
NodePluginResult.waiting(nextExecuteTime)
```

### 4.3 上下文变量

配置中支持使用 `${context.xxx}` 引用流程上下文变量：

```json
{
  "fileName": "${context.fileName}",
  "userId": "${context.userId}"
}
```

## 六、最佳实践

### 6.1 配置验证

实现validateConfig方法验证配置有效性：

```java
@Override
public ValidationResult validateConfig(String configJson) {
    ValidationResult result = ValidationResult.success();
    JSONObject config = JSON.parseObject(configJson);
    
    if (config.getString("endpoint") == null) {
        result.addError("endpoint不能为空");
    }
    
    return result;
}
```

### 6.2 错误处理

使用try-catch捕获异常，返回友好的错误信息：

```java
try {
    // 业务逻辑
} catch (Exception e) {
    log.error("MinIO操作失败", e);
    return NodePluginResult.fail("MinIO操作失败: " + e.getMessage());
}
```

### 6.3 日志记录

使用SLF4J记录日志：

```java
private static final Logger log = LoggerFactory.getLogger(MyPlugin.class);

@Override
public NodePluginResult execute(FlowNode node, Map<String, Object> context) {
    log.info("执行自定义节点: {}", node.getNodeName());
    // ...
}
```

### 6.4 依赖管理

- 使用 `scope=provided` 避免依赖冲突
- 使用maven-shade-plugin打包依赖
- 排除核心模块依赖

## 七、常见问题

### Q1: 插件加载失败？

检查：
1. JAR包是否在plugins目录
2. SPI配置文件是否正确
3. 实现类是否实现NodePlugin接口
4. 查看启动日志错误信息

### Q2: 插件冲突？

如果多个插件有相同的nodeType，后加载的会覆盖先加载的。

### Q3: 如何调试插件？

1. 在IDE中直接运行riverflow-admin
2. 将插件项目添加为依赖
3. 断点调试插件代码

### Q4: 前端组件如何集成？

将前端组件复制到riverflow-ui项目的plugins目录，在流程设计器中动态加载。
