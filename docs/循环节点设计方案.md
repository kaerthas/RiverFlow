# RiverFlow 循环节点设计方案（完整阶段）

> 版本：v2.0  
> 状态：完整阶段实现  
> 目标：在 RiverFlow 流程引擎中完整引入循环节点能力，覆盖串行/并行 `foreach`、`while` 条件循环、循环体子图、嵌套循环、break/continue、异步幂等重入及任务合并。

---

## 1. 背景与目标

### 1.1 背景

当前 RiverFlow 流程引擎内置节点类型为：

- `start` / `end`：起止节点
- `api` / `db` / `script`：数据处理节点
- `condition`：条件分支
- `timer`：定时等待

这些节点可以解决“单步逻辑 + 分支”的问题，但缺少**对集合批量处理**或**条件循环执行**的能力。实际业务中大量场景需要循环：

- 批量调用外部接口处理订单列表
- 对查询结果逐条校验并聚合
- 分页抓取数据直到没有下一页
- 重试某段逻辑直到成功或达到上限

Dify 的 `Loop / Iteration` 节点已经验证了这类需求的标准形态：一个容器节点，内部包含子图，可逐项或按条件反复执行，并输出聚合结果。

### 1.2 完整阶段目标

1. 新增循环节点类型：
   - `foreach` / `end_foreach`：集合迭代循环
   - `while` / `end_while`：条件循环
2. 循环体支持多节点子图，支持嵌套循环。
3. 支持 `break` 中断、`continue` 跳过本次迭代。
4. 支持同步 `executeSync` 和异步 `executeNode` 两种执行模式。
5. 异步模式下具备幂等重入能力，防止任务重复执行和死循环。
6. 支持可选的并行迭代，提升批量处理性能。
7. 异步模式支持“循环任务合并”，一次迭代内部多个节点只产生一个调度任务。
8. 前端画布能够清晰表达循环边界和循环体。

### 1.3 非目标

- 不修改现有节点的执行语义（`api/db/script/condition/timer/start/end` 行为保持不变）。
- 不替换现有 `FlowContext` 的全局变量机制，而是在其之上扩展作用域能力。
- 不引入新的持久化存储介质，复用现有 `context_json` 保存循环状态。

## 2. 术语与定义

| 术语 | 说明 |
|---|---|
| **循环节点（Loop Node）** | 标识循环开始的节点（`foreach` 或 `while`），负责初始化循环状态、解析循环源/条件、驱动第一次迭代。 |
| **循环结束节点（Loop End Node）** | 标识循环体边界的节点（`end_foreach` 或 `end_while`），负责判断是否继续循环、聚合迭代结果、跳转或退出。 |
| **循环体（Loop Body）** | 位于循环节点与循环结束节点之间的子图，是每次迭代实际执行的内容。 |
| **迭代（Iteration）** | 循环体执行一次的过程。 |
| **循环变量** | 每次迭代暴露给循环体的局部变量，如 `item`、`index`。 |
| **聚合结果** | 所有迭代完成后输出的结果数组，通常由循环结束节点产出。 |
| **Loop Frame** | 循环执行时的一个栈帧，保存当前循环的 `nodeId`、`index`、`item`、状态等。 |
| **Scope** | 变量作用域，循环体内变量默认写入当前 scope，退出时 pop。 |
| **任务合并** | 异步模式下，一次完整迭代作为一个任务链执行，减少 FlowTask 数量。 |

## 3. 现状分析

### 3.1 节点类型

```java
public enum FlowNodeTypeEnum {
    START("start", "开始节点", "circle"),
    END("end", "结束节点", "circle"),
    API("api", "接口调用", "cloud"),
    DB("db", "数据库操作", "database"),
    SCRIPT("script", "脚本处理", "code"),
    CONDITION("condition", "条件判断", "diamond"),
    TIMER("timer", "定时等待", "clock");
}
```

### 3.2 执行模型

当前引擎是**扁平图遍历**：

- `FlowEngine.executeNode(instance, node, edges, nodes)` 执行单个节点。
- `TransitionEngine.transition(...)` 根据出边条件找到下一节点，更新 `instance.currentNodeId`，并创建新的 `FlowTask`。
- `FlowScheduler` 每 10 秒扫描 pending/waiting 任务，调用 `FlowEngine.executeNode`。
- `FlowEngine.executeSync` 在单线程内串行执行，直到遇到 `end` 节点。

**关键限制**：没有子图执行能力，也没有局部作用域。

### 3.3 上下文模型

`FlowContext` 是全局单作用域：

```java
public class FlowContext implements Serializable {
    private final Map<String, Object> variables = new ConcurrentHashMap<>();
}
```

所有节点结果统一写入 `nodeResult_<nodeId>`。如果循环体内部节点被执行多次，后续迭代会覆盖前一次结果。

### 3.4 任务模型

每个异步节点执行都会产生一条 `FlowTask` 记录。循环若按节点展开，会导致任务数随迭代次数线性增长。

---

## 4. 设计原则

1. **最小侵入**：尽量复用现有 `FlowEngine`、`TransitionEngine`、`FlowContext`，不推翻现有架构。
2. **显式边界**：通过“循环开始 + 循环结束”双节点明确循环体范围，避免黑盒配置。
3. **状态外置**：循环进度通过 `FlowContext` 持久化到 `context_json`，保证异步模式可重入。
4. **作用域隔离**：循环变量与循环体内部结果必须隔离，避免迭代间污染。
5. **渐进增强**：本版本直接实现完整能力（串行/并行 foreach、while、嵌套、break/continue、幂等、任务合并）。
6. **可观测**：循环执行日志必须携带 `iterationIndex`，方便排查。
7. **向后兼容**：旧流程无需修改即可继续运行；新字段均有默认值。

---

## 5. 总体方案

### 5.1 节点形态

采用**双边界节点**设计：

```text
[start] → [foreach] → [API] → [script] → [end_foreach] → [end]
                         ↑                  |
                         └──────────────────┘
```

- `foreach`：循环开始节点，配置循环源、循环变量、最大迭代数、中断条件等。
- `end_foreach`：循环结束节点，标识循环体结束，负责回跳或退出，并聚合结果。
- `while` / `end_while`：条件循环，结构与 `foreach` 相同，仅入口条件不同。
- 循环体：`foreach`/`while` 与 `end_foreach`/`end_while` 之间的所有可达节点（不包括循环开始节点自身）。

### 5.2 执行流程（串行 foreach）

```text
1. 执行 foreach 节点
   ├── 解析 config，获取集合表达式
   ├── 在 FlowContext 中求值得到集合
   ├── 在 FlowContext 中初始化循环状态
   └── 将 instance.currentNodeId 设置为循环体入口节点

2. 调度器或同步主循环驱动循环体节点执行

3. 循环体执行到 end_foreach 节点
   ├── 将本次迭代结果写入聚合数组
   ├── index++
   ├── 判断是否满足退出条件（index >= size、breakExpr 为 true、达到 maxIterations）
   ├── 若继续：重置 currentNodeId 到循环体入口，开始下一次迭代
   └── 若退出：将聚合结果写入 FlowContext，沿 end_foreach 的出边继续流转
```

### 5.3 核心组件关系

```text
┌─────────────────────────────────────────────────────────────┐
│                         前端画布                              │
│  节点面板 ──► 循环容器渲染 ──► 属性面板配置                     │
```

## 6.1 节点配置模型

### 6.1.1 foreach 节点配置

```json
{
  "loopType": "foreach",
  "sourceExpr": "context.orderList",
  "itemVar": "item",
  "indexVar": "index",
  "resultVar": "loopResult",
  "maxIterations": 100,
  "timeout": 30000,
  "parallel": false,
  "parallelLimit": 5,
  "breakExpr": "context.item.status == 'STOP'",
  "continueOnFail": false,
  "emptyAction": "skip"

```

字段说明：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `loopType` | string | 是 | `foreach` | 循环类型，当前仅 `foreach` |
| `sourceExpr` | string | 是 | - | SpEL 表达式，求值后应为数组或集合 |
| `itemVar` | string | 否 | `item` | 每次迭代暴露的元素变量名 |
| `indexVar` | string | 否 | `index` | 每次迭代暴露的下标变量名 |
| `resultVar` | string | 否 | `loopResult_<nodeId>` | 聚合结果变量名 |
| `maxIterations` | int | 否 | 100 | 最大迭代次数，防止死循环 |
| `timeout` | int | 否 | 30000 | 整个循环节点超时时间（毫秒） |
| `parallel` | boolean | 否 | false | 是否并行执行迭代 |
| `parallelLimit` | int | 否 | 5 | 并行度上限 |
| `breakExpr` | string | 否 | - | SpEL 中断条件，为 true 时退出循环 |
| `continueOnFail` | boolean | 否 | false | 单次迭代失败是否继续下一次 |
| `emptyAction` | string | 否 | `skip` | 集合为空时行为：`skip` 直接退出，`fail` 抛错 |

### 6.1.2 end_foreach 节点配置

```json
{
  "loopNodeId": "node_foreach_001",
  "aggregateExpr": "context.item",
  "outputMapping": [
    { "source": "context.loopResult", "target": "context.orderResults" }
  ]
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `loopNodeId` | string | 是 | 关联的 foreach 节点 ID |
| `aggregateExpr` | string | 否 | 每次迭代要聚合到结果数组的表达式，默认 `context.item` |
| `outputMapping` | array | 否 | 循环退出后，将结果写入全局上下文的映射 |

## 6.2 执行器设计

### 6.2.1 新增执行器

循环相关执行器统一实现 `NodeExecutor` 接口：

```java
@Component
public class ForeachNodeExecutor implements NodeExecutor {
    @Override
    public String getNodeType() { return "foreach"; }

    @Override
    public NodeExecuteResult execute(FlowNode node, FlowContext context) {
        ForeachConfig config = parseConfig(node.getConfigJson());
        LoopState existing = LoopState.from(context.getGlobal(LoopState.key(node.getNodeId())));

        // 幂等：已初始化过则不再重复初始化
        if (existing != null && existing.isInitialized()) {
            return NodeExecuteResult.success()
                    .withNextEntryNode(existing.getBodyEntryNodeId());
        }

        Collection<?> items = evaluateSource(config.getSourceExpr(), context);

        if (items == null || items.isEmpty()) {
            return handleEmpty(config.getEmptyAction(), node, context);
        }

        if (items.size() > config.getMaxIterations()) {
            throw new BusinessException("循环次数超过最大限制: " + config.getMaxIterations());
        }

        // 初始化循环状态
        LoopState state = new LoopState(node.getNodeId(), items, config);
        state.setBodyEntryNodeId(resolveBodyEntryNodeId(node, context.getNodes(), context.getEdges()));
        state.setInitialized(true);
        context.setGlobal(state.getStateKey(), state.toMap());
        context.setGlobal(state.getStartTimeKey(), System.currentTimeMillis());

        // 第一次迭代：将循环变量压入 scope
        pushIterationScope(context, state);

        return NodeExecuteResult.success()
                .withNextEntryNode(state.getBodyEntryNodeId());
    }
}

@Component
public class EndForeachNodeExecutor implements NodeExecutor {
    @Override
    public String getNodeType() { return "end_foreach"; }

    @Override
    public NodeExecuteResult execute(FlowNode node, FlowContext context) {
        EndForeachConfig config = parseConfig(node.getConfigJson());
        String loopNodeId = config.getLoopNodeId();
        LoopState state = LoopState.from(context.getGlobal(LoopState.key(loopNodeId)));
        if (state == null) {
            throw new BusinessException("end_foreach 未找到关联的循环状态: " + loopNodeId);
        }

        // 幂等：当前 index 已聚合过则跳过
        if (!state.isCurrentIndexAggregated()) {
            Object aggregateValue = evaluateAggregate(config.getAggregateExpr(), context);
            state.addResult(aggregateValue);
            state.markCurrentIndexAggregated();
        }

        // 弹出当前迭代 scope
        context.popScope();

        // 判断退出条件
        if (shouldExit(state, config, context)) {
            // 将聚合结果写入全局上下文
            context.setGlobal(state.getResultVar(), state.getResults());
            // 清理循环状态
            context.removeGlobal(state.getStateKey());
            context.removeGlobal(state.getStartTimeKey());
            context.removeGlobal(state.getAggregatedFlagKey());
            return NodeExecuteResult.success().withExitLoop(true);
        }

        // 继续下一次迭代
        state.nextIndex();
        state.clearAggregatedFlag();
        context.setGlobal(state.getStateKey(), state.toMap());
        pushIterationScope(context, state);

        return NodeExecuteResult.success()
                .withNextEntryNode(state.getBodyEntryNodeId());
    }
}
```

### 6.2.2 While 执行器

`WhileNodeExecutor` 与 `ForeachNodeExecutor` 结构类似，区别在于：

- 入口判断 `conditionExpr`，为 false 时直接退出。
- 不维护 `items`/`index`，只维护 `iterationCount`。
- 每次迭代 pushScope，循环变量由循环体自身维护。

```java
@Component
public class WhileNodeExecutor implements NodeExecutor {
    @Override
    public String getNodeType() { return "while"; }

    @Override
    public NodeExecuteResult execute(FlowNode node, FlowContext context) {
        WhileConfig config = parseConfig(node.getConfigJson());
        LoopState state = LoopState.from(context.getGlobal(LoopState.key(node.getNodeId())));

        if (state == null) {
            // 首次进入 while
            if (!evaluateCondition(config.getConditionExpr(), context)) {
                return NodeExecuteResult.success().withExitLoop(true);
            }
            state = new LoopState(node.getNodeId(), config);
            state.setBodyEntryNodeId(resolveBodyEntryNodeId(node, context.getNodes(), context.getEdges()));
            state.setInitialized(true);
            context.setGlobal(state.getStateKey(), state.toMap());
            context.setGlobal(state.getStartTimeKey(), System.currentTimeMillis());
        }

        context.pushScope();
        return NodeExecuteResult.success().withNextEntryNode(state.getBodyEntryNodeId());
    }
}

@Component
public class EndWhileNodeExecutor implements NodeExecutor {
    @Override
    public String getNodeType() { return "end_while"; }

    @Override
    public NodeExecuteResult execute(FlowNode node, FlowContext context) {
        EndWhileConfig config = parseConfig(node.getConfigJson());
        LoopState state = LoopState.from(context.getGlobal(LoopState.key(config.getLoopNodeId())));
        if (state == null) {
            throw new BusinessException("end_while 未找到关联的循环状态");
        }

        context.popScope();
        state.nextIteration();

        if (state.getIterationCount() >= config.getMaxIterations()) {
            return exitLoop(state, context);
        }
        if (System.currentTimeMillis() - state.getStartTime() > config.getTimeout()) {
            throw new BusinessException("while 循环执行超时");
        }
        if (!evaluateCondition(config.getConditionExpr(), context)) {
            return exitLoop(state, context);
        }

        context.setGlobal(state.getStateKey(), state.toMap());
        context.pushScope();
        return NodeExecuteResult.success().withNextEntryNode(state.getBodyEntryNodeId());
    }
}
```

## 6.3 循环状态模型

### 6.3.1 LoopState

```java
public class LoopState {
    private String loopNodeId;           // 循环节点 ID
    private String endNodeId;            // 结束节点 ID
    private String bodyEntryNodeId;      // 循环体入口节点 ID
    private List<Object> items;          // 原始集合（转为 List）
    private int index;                   // 当前迭代下标
    private int total;                   // 总次数
    private int iterationCount;          // while 迭代计数
    private List<Object> results;        // 聚合结果
    private String itemVar;              // 循环变量名
    private String indexVar;             // 下标变量名
    private String resultVar;            // 结果变量名
    private int maxIterations;           // 最大迭代数
    private long startTime;              // 循环开始时间
    private boolean initialized;         // 是否已初始化（幂等用）
    private int lastAggregatedIndex;     // 上次聚合的 index（幂等用）

    public Map<String, Object> toMap() { ... }
    public static LoopState from(Object map) { ... }

    public String getStateKey() { return "_loop_state_" + loopNodeId; }
    public String getStartTimeKey() { return "_loop_start_" + loopNodeId; }
    public String getAggregatedFlagKey() { return "_loop_aggregated_" + loopNodeId; }

    public boolean isCurrentIndexAggregated() {
        return lastAggregatedIndex == index;
    }
    public void markCurrentIndexAggregated() {
        this.lastAggregatedIndex = index;
    }
    public void clearAggregatedFlag() {
        this.lastAggregatedIndex = -1;
    }
}
```

## 6.4 上下文作用域设计

### 6.4.1 设计目标

- 循环变量 `item`、`index` 在每次迭代中独立。
- 循环体内部节点写入 `nodeResult_<nodeId>` 时，不影响循环体外同名节点结果。
- 循环结束后，聚合结果能写入全局上下文。
- **向后兼容**：不在循环体内的节点，行为与旧版本完全一致。

### 6.4.2 FlowContext 改造

```java
public class FlowContext implements Serializable {
    private static final long serialVersionUID = 1L;

    // 全局变量（跨循环共享）
    private final Map<String, Object> globalVariables = new ConcurrentHashMap<>();

    // 作用域栈
    private final Deque<Map<String, Object>> scopeStack = new ArrayDeque<>();

    // 用于图解析时临时持有节点/边（不序列化）
    private transient List<FlowNode> nodes;
    private transient List<FlowEdge> edges;

    public void pushScope() {
        scopeStack.push(new HashMap<>());
    }

    public void popScope() {
        if (!scopeStack.isEmpty()) {
            scopeStack.pop();
        }
    }

    /**
     * 默认写入当前 scope（如果在循环体内）或 global（如果在循环体外）。
     * 为了兼容旧代码，循环体外等价于 setGlobal。
     */
    public void set(String key, Object value) {
        if (!scopeStack.isEmpty()) {
            scopeStack.peek().put(key, value);
        } else {
            globalVariables.put(key, value);
        }
    }

    public void setGlobal(String key, Object value) {
        globalVariables.put(key, value);
    }

    public Object get(String key) {
        for (Map<String, Object> scope : scopeStack) {
            if (scope.containsKey(key)) {
                return scope.get(key);
            }
        }
        return globalVariables.get(key);
    }

    public Object getByPath(String path) {
        // 保持现有 JSONPath 能力
        // 解析时基于合并后的 variables 视图
    }

    public Map<String, Object> toMap() {
        Map<String, Object> merged = new HashMap<>(globalVariables);
        // 从栈底到栈顶合并，后入覆盖先入
        Deque<Map<String, Object>> temp = new ArrayDeque<>(scopeStack);
        while (!temp.isEmpty()) {
            merged.putAll(temp.pollLast());
        }
        return merged;
    }

    public FlowContext fork() {
        FlowContext copy = new FlowContext();
        copy.globalVariables.putAll(deepCopy(this.globalVariables));
        // scopeStack 不拷贝，新上下文无 scope
        return copy;
    }
}
```

### 6.4.3 循环变量写入

每次迭代前：

```java
context.pushScope();
context.set(itemVar, items.get(index));
context.set(indexVar, index);
```

循环体内部节点通过 `context.get("item")` 获取当前元素。

循环体执行到 `end_foreach` 时：

```java
context.popScope();  // 清除本次迭代的 item/index/nodeResult
```

### 6.4.4 节点结果隔离

循环体内部节点的 `nodeResult_<nodeId>` 默认写入当前 scope。如果循环体外需要读取，可以通过 `outputMapping` 显式导出。

> 如需保留循环体内节点在每次迭代中的完整结果，可通过 `resultVar` 聚合或额外配置 `iterationResults`。

## 6.5 引擎流转改造

### 6.5.1 异步模式

`TransitionEngine.transition` 需要识别循环控制结果：

```java
public void transition(FlowInstance instance, FlowNode currentNode,
                       List<FlowEdge> edges, List<FlowNode> nodes,
                       FlowContext context, NodeExecuteResult result) {

    // 1. 如果 result 指定了 nextEntryNodeId（循环跳转）
    if (result.getNextEntryNodeId() != null) {
        FlowNode entryNode = findNode(nodes, result.getNextEntryNodeId());
        if (entryNode != null) {
            instance.setCurrentNodeId(entryNode.getNodeId());
            createPendingTask(instance, entryNode);
            return;
        }
    }

    // 2. 原有逻辑：匹配出边
    ...
}
```

**关键问题**：循环体内部最后一个节点到 `end_foreach` 的边是正常边，`end_foreach` 执行后产生的回跳不是通过 `FlowEdge` 表达，而是通过 `NodeExecuteResult.nextEntryNodeId`。

### 6.5.2 同步模式

`FlowEngine.executeSync` 的主循环需要支持回跳：

```java
while (currentNode != null && !isEnd(currentNode)) {
    NodeExecuteResult result = executor.execute(currentNode, context);

    if (result.getNextEntryNodeId() != null) {
        // 循环回跳
        currentNode = findNode(nodes, result.getNextEntryNodeId());
        instance.setCurrentNodeId(currentNode.getNodeId());
        continue;
    }

    currentNode = findNextNode(instance, currentNode, edges, nodes, context, result);
}
```

同步模式下不需要创建 `FlowTask`，性能最好，适合循环次数不多的场景。

### 6.5.3 循环体识别

引擎需要知道循环体包含哪些节点。推荐**前端写入子图元数据**：

前端在保存流程定义时，把循环体节点 ID 列表写入 `foreach.configJson.bodyNodeIds`。运行时直接读取。

同时后端保留运行时推导作为兜底：

```java
Set<String> findLoopBodyNodes(String loopId, String endLoopId,
                              List<FlowEdge> edges, List<FlowNode> nodes) {
    Set<String> body = new HashSet<>();
    Queue<String> queue = new LinkedList<>();
    queue.add(loopId);

    while (!queue.isEmpty()) {
        String current = queue.poll();
        for (FlowEdge edge : edges) {
            if (edge.getSourceNode().equals(current)) {
                String target = edge.getTargetNode();
                if (target.equals(endLoopId)) continue;
                if (body.add(target)) {
                    queue.add(target);
                }
            }
        }
    }
    return body;
}
```

## 6.6 嵌套循环

### 6.6.1 嵌套结构

```text
[foreach_A] → [foreach_B] → [API] → [end_foreach_B] → [end_foreach_A]
```

### 6.6.2 实现方式

`FlowContext` 的 `scopeStack` 天然支持嵌套：

- 进入 `foreach_A`：pushScope A
- 进入 `foreach_B`：pushScope B
- `context.get("item")` 优先读取最内层 scope 的 `item`

`LoopState` 本身存于 `globalVariables`，通过 `loopNodeId` 区分不同循环。

### 6.6.3 注意事项

- 内层循环的 `resultVar` 不应与外层循环的 `resultVar` 同名。
- 前端画布需要防止循环边界交叉（即不允许 `foreach_A` 的循环体跨越到 `end_foreach_B` 之外）。

## 6.7 break / continue

### 6.7.1 break

`foreach.configJson.breakExpr` 是一个 SpEL 表达式。每次进入 `end_foreach` 执行器时，先判断 `breakExpr`：

```java
if (config.getBreakExpr() != null && SpelUtil.evaluateBoolean(config.getBreakExpr(), context.toMap())) {
    state.setBreak(true);
    return NodeExecuteResult.success().withExitLoop(true);
}
```

> `break` 在 `end_foreach` 判断，意味着循环体至少执行一次。这是 `foreach` 的合理语义。`while` 的入口条件已保证不会进入空循环。

### 6.7.2 continue

`continue` 通过**循环体内 condition 节点 + 跳转边**实现：

- 在循环体内部用 `condition` 判断，满足条件时直接连到 `end_foreach`，跳过本次迭代剩余节点。
- 这种方式复用现有 `condition` 节点，无需新增节点类型。

## 6.8 并行迭代

### 6.8.1 同步模式并行

```java
List<CompletableFuture<Map<String, Object>>> futures = new ArrayList<>();
for (int i = 0; i < items.size(); i++) {
    final int index = i;
    final Object item = items.get(index);
    futures.add(CompletableFuture.supplyAsync(() -> {
        FlowContext iterationContext = context.fork();
        iterationContext.pushScope();
        iterationContext.set(itemVar, item);
        iterationContext.set(indexVar, index);
        executeLoopBodySync(iterationContext, bodyNodes, bodyEdges);
        return iterationContext.toMap();
    }, loopExecutor));
}

// 等待所有迭代完成并聚合（保持顺序）
List<Map<String, Object>> iterationResults = new ArrayList<>();
for (int i = 0; i < futures.size(); i++) {
    iterationResults.add(futures.get(i).join());
}
```

### 6.8.2 异步模式并行

异步模式并行更复杂：

- 每个迭代作为独立的子任务链启动。
- 需要一个“汇聚任务”在所有迭代完成后触发 `end_foreach`。
- 可以引入任务依赖表或在 `FlowContext` 中记录未完成的迭代任务 ID。

**本版本实现**：异步模式暂不支持并行迭代，若 `parallel=true` 则转为串行执行并记录警告。

### 6.8.3 上下文 fork

并行执行必须深拷贝 `FlowContext`，否则多个迭代会互相污染。

```java
public FlowContext fork() {
    FlowContext copy = new FlowContext();
    copy.globalVariables.putAll(deepCopy(this.globalVariables));
    return copy;
}
```

## 6.9 超时与防死循环

### 6.9.1 最大迭代数

`maxIterations` 后端强制校验：

```java
if (items.size() > config.getMaxIterations()) {
    throw new BusinessException("循环次数超过最大限制: " + config.getMaxIterations());
}
```

### 6.9.2 超时

- 同步模式：复用 `executeSync` 的 `deadline` 全局超时。
- 异步模式：`ForeachNodeExecutor` 启动时记录 `startTime`，每次 `end_foreach` 判断 `System.currentTimeMillis() - startTime > timeout`。

### 6.9.3 幂等

异步模式下，调度器重入时可能重复执行同一节点。循环节点需要：

- 在 `FlowContext` 中记录当前 `index` 和 `lastAggregatedIndex`。
- `ForeachNodeExecutor` 和 `EndForeachNodeExecutor` 都是幂等的：
  - 如果当前 index 已经执行过，不再重复初始化或聚合。
  - 通过 `FlowTask` 的 `executeCount` 和状态进行二次校验（复用现有逻辑）。

---

## 6.10 异步任务合并

为减少 `FlowTask` 数量，异步模式下一次完整迭代作为一个任务链执行：

```java
// 当 TransitionEngine 检测到 nextEntryNodeId 且目标为循环体入口时，
// 不创建新的 pending 任务，而是直接在当前线程继续执行循环体内部节点。
// 循环体内部节点按普通节点创建任务，但由同一次调度调用链驱动。
```

更激进的合并策略（可选）：

- 循环体内部所有节点合并为单个 `FlowTask`，由 `FlowEngine` 在一次调用中连续执行。
- 需要在 `FlowTask` 中增加 `loopInternal` 标记，调度器识别后跳过内部节点的单独调度。

**本版本实现**：采用“同链连续执行”策略，即循环回跳不创建新任务，循环体内部节点仍创建任务但由同一调度链驱动，避免调度器重复扫描。

校验规则：

1. `foreach` 和 `end_foreach` 必须成对出现；`while` 和 `end_while` 必须成对出现。

4. `foreach` 的 `sourceExpr` 不能为空。
5. `maxIterations` 必须在 1~10000 之间。
6. `end_foreach` 的 `loopNodeId` 必须存在且对应一个 `foreach` 节点。
7. 同步流程不支持 `timer` 节点（已有校验），循环节点无额外限制。

现有 `executeSync` 接口可直接用于调试循环节点。

## 11. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 任务爆炸（异步模式） | 循环次数多导致大量 FlowTask | 任务合并：循环回跳不创建新任务，同链驱动 |
| 上下文污染 | 多次迭代结果互相覆盖 | 引入 scope 机制 |
| 死循环 | 流程无法正常结束 | maxIterations 强制限制、timeout 超时 |
| 画布复杂度 | 循环容器交互难实现 | 先简化容器渲染，仅做视觉框 |
| 并行迭代数据竞争 | 多个迭代读写同一变量 | fork 独立 FlowContext，聚合时再合并 |
| 与 condition 边语义冲突 | 循环回跳边和分支边混淆 | 回跳边默认隐藏，流转优先使用 NodeExecuteResult |
| 老版本流程兼容 | 旧流程没有循环节点 | 新字段都设默认值，枚举增加不破坏旧数据 |
| 幂等性不足 | 异步重入导致重复聚合 | LoopState 记录 initialized/lastAggregatedIndex |

## 13. 决策记录

1. **为什么用双边界节点而不是单个容器节点？**  
   双边界节点与现有扁平图模型兼容最好，不需要重构图存储结构，前端也更容易用现有边和节点表达。

2. **为什么把循环状态存在 context_json 而不是新表？**  
   复用现有持久化机制，改动最小。异步模式重入时直接从 instance 恢复状态。

3. **为什么异步模式暂不支持并行迭代？**  
   并行会引入上下文 fork、任务汇聚、结果合并等复杂度。先保证串行稳定，后续再扩展异步并行。

4. **为什么推荐运行时由前端写入 bodyNodeIds？**  
   避免后端每次运行时都做图解析，也避免循环边界在复杂图中推导错误。

5. **为什么默认 set() 写入当前 scope？**  
   循环体内部节点结果需要隔离，避免多次迭代互相覆盖。循环体外 scopeStack 为空，等价于旧行为，保持向后兼容。

6. **为什么 break 在 end_foreach 判断？**  
   foreach 语义下循环体至少执行一次，在结束节点判断 break 最自然，也避免每次迭代开始节点都判断。
