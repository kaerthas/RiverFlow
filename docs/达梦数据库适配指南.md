# 达梦数据库适配指南

RiverFlow 平台 master 主库支持 **MySQL 8.0（默认）** 和 **达梦 DM8** 两种数据库，通过 Spring Profile 切换，互不影响。业务数据源（用户在"数据源管理"中注册的外部库）的多数据库支持与本文无关，另行参见数据源管理功能。

---

## 1. 安装达梦 JDBC 驱动

达梦驱动不在 Maven 中央仓库，需手动安装到本地仓库（仅需执行一次）：

1. 从达梦数据库安装目录 `drivers/jdbc/` 下获取 `DmJdbcDriver18.jar`，复制到 `riverflow-admin/lib/`。
2. 在仓库根目录执行：

```bash
mvn install:install-file -Dfile=riverflow-admin/lib/DmJdbcDriver18.jar -DgroupId=com.dameng -DartifactId=DmJdbcDriver18 -Dpackaging=jar -Dversion=8.1.3.140
```

3. 版本号需与父 `pom.xml` 中 `<dm.version>` 保持一致（当前 8.1.3.140）。使用其他版本驱动时，先改 `<dm.version>` 再执行安装命令。

> 该方式与 `river-ixa-gateway` 模块引入本地 SDK 的做法一致。驱动打入 spring-boot fat jar，无需运行时额外配置 classpath。

## 2. 达梦建库

### 2.1 创建用户与模式

在达梦管理工具（DM 管理工具 / disql）中以 SYSDBA 执行 **`db/dm/create_user_dm.sql`**，核心语句：

```sql
CREATE USER RIVERFLOW IDENTIFIED BY "Riverflow@123";   -- 默认策略：最小 9 位且不得与用户名相同
GRANT RESOURCE, PUBLIC TO RIVERFLOW;
```

达梦中用户与模式（schema）同名，应用 JDBC URL 中的 `RIVERFLOW` 即指向该模式。

### 2.2 执行表结构与初始数据脚本

依次执行（**无需关心执行账号**：脚本中对象名均带 `RIVERFLOW.` 模式前缀，SYSDBA 或 RIVERFLOW 登录执行均可）：

1. `db/dm/river_online_schema_dm.sql`（27 张表结构）
2. `db/dm/river_online_data_dm.sql`（基础数据）

> ⚠️ 达梦中对象归属"执行账号的同名模式"。若不慎用 SYSDBA 执行了**无模式前缀**的脚本，表会建到 SYSDBA 模式下（应用连 RIVERFLOW 模式将报"表不存在"）。清理方式：SYSDBA 登录执行 `db/dm/cleanup_sysdba_dm.sql`，再重跑带前缀脚本。

表结构脚本由 MySQL 版本（`db/riverflow_init.sql` 等）翻译/导出而来。`db/dm/` 目录下留有部分已翻译的参考脚本（`*_dm.sql`），**正式脚本以实际重新导出的版本为准**。

从 MySQL 方言翻译为达梦 DM8 的规则速查：

| MySQL 写法 | 达梦 DM8 写法 |
|---|---|
| 反引号 `` `col` `` | 去掉引号（无引号标识符统一按大写存储，与 MyBatis 生成的 SQL 兼容） |
| `ENGINE=InnoDB CHARACTER SET ... ROW_FORMAT ...` | 整段删除 |
| `bigint(20)` / `int(11)` / `tinyint(4)` | `BIGINT` / `INT` / `TINYINT`（去宽度） |
| `varchar(n) CHARACTER SET ... COLLATE ...` | `VARCHAR(n)` |
| `datetime(0)` | `TIMESTAMP` |
| `json` / `text` / `longtext` | `CLOB`（Java 实体侧为 String，读写无感） |
| `AUTO_INCREMENT` | 删除（应用层 MyBatis-Plus 雪花 ID 显式赋值） |
| `DEFAULT CURRENT_TIMESTAMP(0)` | `DEFAULT CURRENT_TIMESTAMP` |
| `ON UPDATE CURRENT_TIMESTAMP(0)` | 删除（应用层 `MetaObjectHandler` 已自动填充 updateTime） |
| 列尾 `COMMENT '...'` | 表后补 `COMMENT ON COLUMN 表.列 IS '...'` |
| 表级 `COMMENT = '...'` | 表后补 `COMMENT ON TABLE 表 IS '...'` |
| 表内联 `INDEX idx(c) USING BTREE` | 表后补 `CREATE INDEX idx ON 表(c)` |
| `CREATE TABLE IF NOT EXISTS` | `CREATE TABLE` |
| `ALTER TABLE t ADD COLUMN c ... AFTER x` | 删除 `AFTER x`（达梦不支持列定位）；一条 ALTER 带多个 ADD COLUMN 需拆成多条 |
| `INSERT ... ON DUPLICATE KEY UPDATE c=VALUES(c)` | 达梦不支持，初始化脚本改为纯 INSERT（重复执行前先清空表），或改用 `MERGE INTO` |
| `NOW()` | `CURRENT_TIMESTAMP` |
| `SET NAMES ...` / `SET FOREIGN_KEY_CHECKS=...` | 删除 |

## 3. 启用达梦主库

配置文件：`riverflow-admin/src/main/resources/application-dm.yml`

```yaml
spring:
  datasource:
    dynamic:
      datasource:
        master:
          url: jdbc:dm://localhost:5236/RIVERFLOW?compatibleMode=mysql&characterEncoding=utf-8
          username: RIVERFLOW
          password: riverflow        # 生产环境用 Jasypt 加密，格式 ENC(密文)
          driver-class-name: dm.jdbc.driver.DmDriver
```

启动时激活 profile：

```bash
# 方式一：命令行参数
java -jar riverflow-admin.jar --spring.profiles.active=dm
mvn spring-boot:run -Dspring-boot.run.profiles=dm

# 方式二：环境变量（Docker/K8s 场景）
SPRING_PROFILES_ACTIVE=dm
```

不激活 `dm` profile 时一切照旧，使用 MySQL（`application.yml` 未做任何改动）。

## 4. 代码适配说明（已内置，无需改动）

| 适配点 | 说明 |
|---|---|
| 分页插件 | `MyBatisPlusConfig` 中 `PaginationInnerInterceptor` 不再硬编码 `DbType.MYSQL`，按当前数据源 JDBC URL 自动识别，MySQL/达梦均生成正确分页 SQL |
| `LIMIT n` 语法 | 代码中少量 `.last("LIMIT 1")`、`LIMIT 100` 写法，达梦 8 原生兼容，无需修改 |
| 连接池 | Druid 1.2.21 支持达梦；`validation-query: SELECT 1` 双库通用 |
| 主键生成 | `id-type: assign_id` 雪花 ID，应用层赋值，不依赖数据库自增 |
| 时间字段填充 | `MetaObjectHandler` 自动填充 createTime/updateTime，替代 MySQL 的 `ON UPDATE CURRENT_TIMESTAMP` |

## 5. 已知差异与注意事项

1. **`wf_region.level` 列名**：`LEVEL` 是达梦层次查询伪列关键字。达梦版 DDL 中该列保持不加引号的 `level`；若在执行或查询中遇到保留字报错，将该列以双引号大写 `"LEVEL"` 创建即可（达梦无引号标识符按大写匹配）。
2. **`DEFAULT ''` 空串默认值**：达梦在 Oracle 兼容模式下会把空字符串按 NULL 处理，依赖空串默认值的列需注意（如 `create_by`）。建议达梦实例使用 MySQL 兼容模式（JDBC URL 已带 `compatibleMode=mysql`）。
3. **json 列**：MySQL 的 `json` 类型在达梦中为 `CLOB`，内容就是 JSON 文本，平台代码按 String 处理，无行为差异；但无法在 SQL 层使用 JSON 路径查询（平台未使用该能力）。
4. **达梦大小写**：无引号标识符统一转大写存储。平台所有 SQL（MyBatis 生成 + 注解）均不带引号，不受影响；手写 SQL 工具查询时注意表名实际为大写。
5. **`INSERT` 多行 VALUES**：部分达梦版本对多行 VALUES 支持有差异，初始化脚本建议逐行 INSERT。
6. **MySQL JSON 生成列**：`GENERATED ALWAYS AS (json_extract(...)) STORED` 达梦不支持（如 `third_project_data` 的 `v_*` 列），达梦版脚本已降级为普通列并附注释；如需取 JSON 内字段，在应用层解析 CLOB 中的 JSON 文本。
7. **索引名全局唯一**：MySQL 索引名只需表内唯一，达梦要求**模式内全局唯一**。达梦版脚本已将所有索引重命名为 `idx_<表名>_<列>` 形式，并在每个 `CREATE INDEX` 前加 `DROP INDEX IF EXISTS` 兜底，重复执行脚本不会冲突。
8. **Map 结果集列名大小写**：达梦/JDBC 返回大写列名（`APP_ID`），MySQL 返回小写（`app_id`），`listMaps` 等 Map 返回场景用小写 key 取值会得到 null（典型报错 `For input string: "null"`）。已在 `MyBatisPlusConfig` 注册 `ObjectWrapperFactory`，将所有 Map 结果集包装为大小写不敏感，双库取值行为一致，业务代码无需改动。

## 6. 常见问题

- **启动报 `Could not find artifact com.dameng:DmJdbcDriver18`**：驱动未安装到本地仓库，执行第 1 节的 install-file 命令。
- **启动报 `dm.jdbc.driver.DmDriver` 找不到 / ClassNotFound**：fat jar 中缺驱动，确认依赖未被 scope 排除后重新 `mvn package`。
- **执行 SQL 报"无效的表名或视图名"**：JDBC URL 中的模式名与达梦用户名不一致，或当前用户对该模式无权限。
- **分页 SQL 报错**：确认 JDBC URL 以 `jdbc:dm://` 开头（分页插件靠 URL 识别数据库类型）。
